Add Verlass to your email

Verlass is free for personal, commercial, school, and enterprise use. It has no server of its own: everything runs in your own Google or Microsoft 365 account. Choose where your organization keeps its mail.

Gmail

Verlass for Gmail is a Google Workspace add-on written in Google Apps Script. Tickets and settings are rows in one Google Sheet in your own Drive. It works with Google Workspace accounts and with free Gmail accounts.

New in version 2.0.0. The Gmail add-on has been tested against a simulated Gmail and Google Sheets, and has not yet been run in a live Google account. Try it with a few people first, and please report what you find.

Standard install

  1. Download verlass-gmail.zip and unzip it.
  2. Go to script.google.com, select New project, and rename the project Verlass.
  3. Select Project Settings (the gear) and check Show "appsscript.json" manifest file in editor.
  4. Go back to the Editor. For each of Addon, Cards, Core, Service, SettingsCards, and Store: select the plus sign next to Files, choose Script, type the name, and replace everything in the new file with the contents of the matching .gs file from the package. Then delete the starter file Code.gs.
  5. Open appsscript.json and replace everything in it with the package's appsscript.json. If you are not in the US Eastern time zone, change America/New_York to yours, for example Europe/Berlin. Save.
  6. Select Deploy, then Test deployments, then Install, then Done.
  7. Open Gmail and reload it. Select the Verlass icon in the panel on the right, select Authorize access, and approve the permissions. With a free Gmail account, Google first says that it has not verified this app, because the project is your own. Select Advanced, then Go to Verlass (unsafe).
  8. Enter your organization's name, choose a starting set of lists, and select Create the help desk. Verlass creates the Google Sheet in your Drive and makes you the first administrator.
  9. Open Settings, then Team, and add the people who will work on tickets. Then select Open the spreadsheet and share the Sheet, as Editor, with everyone who will use the help desk. A Google group makes this one step.

Other peopleA test deployment is installed per person, and Google lets a person install it only if they can edit the project. In Google Workspace they must also belong to the owner's organization. Anyone who can edit the project can change what it does, so share it only with people you would trust as administrators, and have each one select Deploy, Test deployments, and Install. For everyone else, publish the add-on for your organization (below). Sharing between free Gmail accounts has not been tested.

Private install

The Private install splits Verlass in two. A small service project owns the Sheet and runs as one account, ideally a shared one such as helpdesk@your-domain. The add-on project is what people install. It proves who each person is with a Google sign-in token, and the service answers only for that person.

  1. Download verlass-gmail-private.zip and unzip it. Sign in to Google as the account that should own the help desk.
  2. The service. At script.google.com create a project named Verlass service. Show the manifest file as in the Standard install, add the script files Core, Service, and Store from the package's service folder, delete Code.gs, and replace appsscript.json with the one in that folder.
  3. Select Deploy, then New deployment. Choose the type Web app, set Execute as to Me and Who has access to Anyone, and select Deploy. Approve the permissions, then copy the Web app URL. It ends in /exec.
  4. Recommended: in Project Settings, under Script properties, add a property named ALLOWED_DOMAIN with your domain, for example example.org. The service then refuses accounts from anywhere else.
  5. The add-on. Create a second project named Verlass. Add the script files Addon, Cards, Core, and SettingsCards from the package's addon folder, delete Code.gs, and replace appsscript.json with the one in that folder.
  6. In this project's Project Settings, under Script properties, add a property named SERVICE_URL and paste the web app URL from step 3.
  7. Select Deploy, then Test deployments, then Install. Open Gmail as the owner account, open Verlass, authorize it, and select Create the help desk.
  8. Open Settings, then Team, and add your team. Do not share the Sheet with anyone who should not read every ticket.

Other peopleTo give the add-on to a few trusted people, share the add-on project (never the service project) with them as Editor and have each one select Deploy, Test deployments, and Install. Anyone who can edit the add-on project can change its code and could act as another person, so for ordinary staff publish it for your organization (below). Only the time zone in the service project's appsscript.json matters; the add-on shows times the way the service does.

Why the web app is open to "Anyone"The add-on reaches the service over the internet, so Google must let the request in. The service then checks every request itself: it must carry a Google sign-in token for a verified account, from your domain if you set ALLOWED_DOMAIN, issued to your own add-on project. The first time the owner or an administrator opens the add-on, the service remembers that project and refuses every other. A request without those gets an error and nothing else. Some organizations do not allow web apps that are open to anyone; in that case use the Standard install.

For everyone in a Google Workspace organization

To give Verlass to a whole domain, an organizational unit, or a group, publish your add-on project in the Google Workspace Marketplace for your organization only. Google calls this a private app: it is visible only inside your organization and needs no review by Google. The choice between private and public cannot be changed afterward. You need a Google Workspace administrator and a Google Cloud project. Google's guides have the current screens: Publish an add-on and Publish to the Marketplace.

  1. In the Google Cloud console, create a project in your organization. Under APIs and Services, set up the OAuth consent screen with the user type Internal.
  2. In the Apps Script project that people install (the Standard project, or the add-on project of a Private install), open Project Settings, select Change project, and enter the Cloud project's number.
  3. Select Deploy, then New deployment, choose the type Add-on, and deploy. Copy the Deployment ID.
  4. In the Cloud console, enable the Google Workspace Marketplace SDK. On its App Configuration page choose Private visibility, select Google Workspace add-on, paste the Deployment ID, and list the same permissions as the project's appsscript.json.
  5. Fill in the Store Listing. You can use the icons in this site's assets/icons folder, the small banner at assets/brand/verlass-banner-220x140.png, and a screenshot of the demo (Google asks for one of 1280 by 800 pixels), and link to this site's privacy, terms, and help pages. Select Publish.
  6. In the Google Admin console, go to Apps, then Google Workspace Marketplace apps, add the app, and install it for everyone or for chosen groups.

Private install: publish before people use itThe service remembers which add-on project it answers. Moving the add-on project to a Cloud project (step 2) is expected to change that identity. If people then see "made for a different add-on", delete the script property ALLOWED_AUDIENCE in the service project and have the owner open the add-on first.

With clasp, for IT teams and developers

  1. Turn on the Apps Script API at script.google.com/home/usersettings.
  2. Install and sign in: npm install -g @google/clasp, then clasp login.
  3. In an empty folder run clasp create-script --type standalone --title "Verlass". Copy the package's files into the folder, delete any Code.js that clasp made, and let the package's appsscript.json replace clasp's.
  4. Run clasp push --force, then clasp open-script, and continue from the Deploy step above. Versions of clasp before 3 call these two commands clasp create and clasp open.

Optional: create a ticket from the open email

Verlass can turn the email you are reading into a ticket. This needs one more permission, to read the open message, so it is off by default. To turn it on, edit appsscript.json in the project that people install: add "https://www.googleapis.com/auth/gmail.addons.current.message.readonly" to oauthScopes, and change "gmail": {} to:

"gmail": {
  "contextualTriggers": [
    { "unconditional": {}, "onTriggerFunction": "onGmailMessage" }
  ]
}

Everyone approves the new permission the next time they open Verlass. A Create from this email button then appears whenever a message is open.

Updating

Add-ons installed this way do not update themselves. When a new version comes out, replace the script files with the new package's files and save. Your script properties, your Sheet, and your settings are not touched. For a Private install, also open Deploy, then Manage deployments in the service project, edit the web app, and choose New version, so its address stays the same. If you published the add-on for your organization, edit its add-on deployment the same way and choose New version; until then people keep the old code.

What to know

  • Google limits how much email an account sends through Apps Script each day: about 100 recipients for a free account and 1,500 for a Google Workspace account. In a Private install every notice comes from the owner's account, so a busy help desk on a free account can reach the limit. Email that could not be sent is noted in the ticket's activity.
  • The help desk's time zone is recorded when it is set up, from the project's appsscript.json, and can be changed under Settings, Hours.
  • A ticket's card shows its latest 20 messages. The Messages tab of the Sheet holds all of them.

Outlook

Verlass for Outlook is an Office add-in for Outlook on the web, the new and classic Outlook for Windows, Outlook for Mac, and Outlook for iOS and Android. Tickets are items in a SharePoint list in your own Microsoft 365 tenant, reached through Microsoft Graph as the signed-in person. It needs work or school accounts with Exchange Online mailboxes and SharePoint, which Microsoft 365 Business Basic, Standard, and Premium and the enterprise and education suites include. Personal Outlook.com accounts are not supported, and neither are the separate government and China clouds.

New in version 2.0.0. The Outlook add-in has been tested against a simulated Microsoft 365, not yet in a live tenant. Try it with a few people first, and please report what you find.

What an administrator does, once

You need a Global Administrator for granting consent, for creating the lists, and for deploying the add-in. The same person must be an Owner of the help desk site.

  1. Create a SharePoint site for the help desk. In SharePoint select Create site, choose Team site, name it, for example Help Desk, and set its privacy to Private. Make the help desk team Owners of the site. Then select the gear, Site permissions, Advanced permissions settings, open the Visitors group, select New, and add Everyone except external users. Do not add staff as Members: Members can change lists, including the help desk's settings. Copy the site's address, such as https://contoso.sharepoint.com/sites/helpdesk.
  2. Register the app. In the Microsoft Entra admin center, go to App registrations and select New registration. Name it Verlass, keep Accounts in this organizational directory only, and under Redirect URI choose Single-page application (SPA) and enter brk-multihub://verlass.alyssaagard.dev. Select Register.
  3. On the app's Authentication page, add two more single-page application redirect URIs: https://verlass.alyssaagard.dev/app/blank.html and https://verlass.alyssaagard.dev/app/auth.html. Save.
  4. On API permissions, select Add a permission, then Microsoft Graph, then Delegated permissions, and add Sites.Selected and Mail.Send. User.Read is already there. Then select Grant admin consent.

  1. Create the lists. Select Open the browser app to finish setup above and sign in as a Global Administrator who is also an Owner of the site. Open I am the administrator and select 1. Create the lists. Microsoft asks you to approve one higher permission, Sites.FullControl.All (or Sites.Manage.All if you chose the wider access above). Leave Consent on behalf of your organization unchecked, so it applies to your account only. Verlass uses it to give the add-in access to this one site and to create three lists, and does not store it. Then enter your organization's name and select 2. Create the help desk.
  2. Remove the setup permission. It is no longer needed. In the Microsoft Entra admin center, open Enterprise applications, choose Verlass, then Permissions, and on the User consent tab remove that permission. Microsoft's page Review permissions granted to enterprise applications has the current steps.
  3. Set who can see what. On the site, open Site contents and for each list choose Settings:
    • Help Desk Tickets: under Advanced settings, Item-level Permissions, choose Read items that were created by the user and Create items and edit items that were created by the user. Under Permissions for this list, stop inheriting permissions and grant Everyone except external users the level Contribute. Site Owners keep Full Control, which is what lets the team see every ticket.
    • Help Desk Notes: under Permissions for this list, stop inheriting permissions and remove every group except the Owners. Internal notes live here.
    • Help Desk Settings: leave it as it is. Visitors can read it, and Owners can change it.
  4. Deploy the add-in. In the Microsoft 365 admin center, go to Settings, then Integrated apps. Select Upload custom apps, choose Office Add-in as the app type, and upload verlass-manifest.xml. Choose who gets it and finish the deployment. Microsoft says it can take up to 24 hours to appear, sometimes longer.
  5. Add your team. Open Verlass in Outlook, open the menu, choose Settings, then Lists, then Team.

For one person, or to test first

In Outlook on the web, open aka.ms/olksideload, choose My add-ins, then Add a custom add-in, then Add from File, and choose your manifest. The add-in then follows your account to Outlook on Windows, Mac, and mobile.

Where to find it

Open any message. In Outlook on the web and the new Outlook, select Apps in the message's toolbar and choose Verlass. In classic Outlook for Windows and Outlook for Mac, select the Help desk button on the ribbon. Pin the panel to keep it open. On a phone, open a message, select the three dots, and choose Verlass. Outlook opens add-ins from an open message, which also gives you the Create from the open email button. The same help desk opens in any browser at https://verlass.alyssaagard.dev/app/, which suits a team that wants its queue on a large screen.

What to know

  • Email notices are sent from the mailbox of the person who acts, and only while their Verlass panel is open.
  • When a team member creates a ticket for someone else, that person follows it by email. It does not appear under their own requests, because SharePoint shows people only the items they created.
  • SharePoint, not Verlass, enforces who can read what. A person who opens the list in SharePoint directly can change the fields of their own tickets.
  • Round robin assignment picks a team member evenly at random, because SharePoint keeps no counter that requesters could update.
  • Lists show at most 12,000 tickets, and one ticket's conversation can hold about 60,000 characters.
  • In the browser app, Microsoft's sign-in lasts about a day. When it ends, the app shows a Sign in again button.
  • Renaming a status, priority, category, or location renames it on the tickets that use it, one ticket at a time, which can take a while on a large list.
